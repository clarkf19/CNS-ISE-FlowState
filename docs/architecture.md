# Architecture

```
            ┌────────────────────────── Secure Gateway ──────────────────────────┐
 Client ──► │ codec ─► handshake (identity + X25519 + HKDF) ─► session manager   │
 (client/)  │       └► pipeline: session → decrypt → replay → freshness → authz  │ ──► Backend
            │                                   │                                │    (backend/)
            │                         SecurityEvent per decision ─► audit log    │
            └────────────────────────────────────────────────────────────────────┘
```

## Packages

| Package | Responsibility | Depends on |
|---|---|---|
| `core/` | Wire codec, messages, crypto facade, pipeline engine, reason codes, events, clock, config | `cryptography` (facade only) |
| `identity/` | Key files, client registry, Ed25519 authentication of ClientHello, key CLI | core |
| `handshake/` | Signed X25519 handshake (both sides), HELLO replay cache, HKDF key schedule | core, identity |
| `session/` | Session table, expiry, request limits, key destruction; pipeline stage 1 | core, handshake |
| `record/` | AES-256-GCM sealing/opening of requests and responses; pipeline stage 2 | core |
| `replay/` | Nonce cache, sequence ordering, freshness window; pipeline stages 3–4 | core |
| `authz/` | RBAC policy (deny by default); pipeline stage 5 | core |
| `backend/` | Transaction service, token-protected backend server, forwarding client | core |
| `audit/` | Hash-chained JSONL security log, verification, CLI | core |
| `gateway/` | Server wiring all of the above; in-process runtime for tests and demos | all |
| `client/` | SecureClient SDK and demo CLI | core, handshake, record |
| `attacks/` | MITM proxy and attack scenarios | gateway runtime, client |
| `eval/` | Baseline proxy, benchmarks, report generation | attacks, gateway runtime |
| `dashboard/` | Local web UI over the live gateway, attack suite and evaluation | gateway runtime, client, attacks, eval |

## Design rules

1. **One crypto entry point.** Only `core/crypto.py` touches the `cryptography`
   library. Key sizes are validated there, ephemeral keys cannot be reused, and
   tag failures become a single `AuthenticationFailed` type.
2. **Canonical encoding for anything signed or authenticated.** Signatures and
   AAD are always computed over `encode_fields(...)` with a domain-separation
   label.
3. **Stages decide, the gateway logs.** Stages raise `SecurityError(reason)`.
   The gateway turns every verdict into exactly one `SecurityEvent`. Logging
   can be changed without touching security logic.
4. **No state change before full acceptance.** Replay state, sequence numbers
   and request counters change only in the pipeline commit phase.
5. **Fail closed.** Malformed input, unknown identifiers and unexpected
   exceptions all reject.
6. **Injectable time.** Every time-dependent component takes a `Clock`, so
   expiry and freshness can be tested deterministically and demonstrated live
   with `OffsetClock`.

## Concurrency model

The gateway runs on one asyncio event loop. A request's pipeline run
(check → commit) contains no `await`, so it is atomic with respect to other
requests. Forwarding to the backend happens after the commit. The session table
and registries also use locks, so they are safe to share with threads such as
the test runtime.

## Runtime layout

```
config/gateway.toml   ports, TTLs, windows, file locations
config/policy.toml    roles → permissions, operations → permission
keys/                 generated by `flowstate-keys bootstrap` (git-ignored)
logs/audit.jsonl      hash-chained security log (git-ignored)
```
